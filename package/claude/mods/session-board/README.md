# session-board

チャットが流れても、このセッションの現在地が常に見えるようにするペイン。

## 出すもの

各欄は最大 5 件、1 件 1 行。

- 概要: いま何をしていて、どの段階か
- あなたの判断待ち: Claude が求めていて未回答のもの。短い答えで足りる判断には、回答候補を最大 4 つボタンで出す（Claude が会話で示した選択肢、なければ「はい / いいえ」などの候補）。自由記述でしか答えられない判断にはボタンを出さない。押すとその答えをユーザーの発話として送る
- プロンプトの真上の帯: Claude の直前の返答で求められた判断のうち、回答候補があるものを同じボタンで出す。押すと送信し、帯から消える
- Claude が決めたこと: ユーザーが決めたほうがよさそうなものだけ。各行の「議論」を押すと、理由と他の選択肢の説明を求め、答えるまで実装を止めるよう送る
- PR: 番号、Draft / Ready / Merged、CI、レビュー判定、未解決の指摘数、競合の有無。行をクリックするとブラウザで PR を開く

## 動き

- 主セッションのターンが終わるたびに `$.model.fork`（effort は low）で会話全体を読み直し、上の 3 欄を丸ごと置き換える。前回の内容も渡すので、同じ項目の文言は変わりにくい。
- PR は現在のブランチを `gh` で読む。セッション開始時、ターン終了時、2 分ごとに更新する。
- ペインはセッション開始時に開く。閉じたら `/board` で開き直す。「更新」ボタンで手動更新できる。要約を取りにいっている間は、ボタンの横に「更新中…」と出る。
- fork や `gh` が失敗したら前回の内容を残し、「更新失敗」と時刻を出す。resume 直後など要約を作れないときは、前回の内容を残して「いまは要約できません」と出す。resume したセッションでは、最初のターンが終わるまで要約できない。PR のないブランチは「PR なし」と出す。状態の行（更新ボタン、更新中、要約の時刻、エラー）は、内容が長くても見えるようペインの先頭に置く。
- 更新中に次のターンが終わったら、後から始めた更新の結果だけを採用する。

## やらないこと

- 複数セッションや worktree の横断表示
- 状態と無関係な定型プロンプトのボタン
- リリースや検証の自動化

## 検証

`claude plugin validate .` と `claude plugin test .` を実行する。表示中の状態はセッション内（`$.state`）に持つ。最後の要約だけは `$.store` に会話ファイルのパスを鍵にして保存し、resume 直後に読み戻す（最大 200 セッション分、古い順に捨てる）。
